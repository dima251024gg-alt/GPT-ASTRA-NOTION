# Аквамарин.Документы

Внутренняя система документооборота турагентства. Русскоязычный интерфейс, данные вводятся один раз, документы формируются из проверенных карточек.

Разработка по спринтам S1–S6. В репозитории хранится только код и синтетические данные; реальные паспорта, ключи, базы и резервные копии коммитить запрещено.

⚠️ Репозиторий публичный. Не добавляйте сюда реальные реквизиты, ключи, сканы документов и выгрузки базы.

## Как запустить (локальный демонстрационный режим)

```bash
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt
python3 -m unittest discover -s tests -v
```

Переменные окружения: `APP_ENV` (`development` по умолчанию), `DATA_DIR`, `DATABASE_URL`, `PUBLIC_URL`, `RETENTION_YEARS`, `PACKAGE_DAYS`, `OCR_PROVIDER` (`local` | `russian-api` | `manual`).

В режиме `APP_ENV=production` приложение не запустится без PostgreSQL, HTTPS, ключей `DATA_KEY`/`TOKEN_KEY`/`AUDIT_KEY`, реальных провайдеров и подтверждений `LEGAL_APPROVED`, `INFRA_RU_ATTESTED`. Это сделано намеренно: код не может сам обеспечить локализацию данных и правовую проверку.

## Статус реализации

- S1 — модель данных (31 таблица), шифрование ПД (AES-256-GCM), вход с 2FA, ролевые ограничения, неизменяемый аудит с хеш-цепочкой, CRUD. **Готово, покрыто тестами.**
- S2 — файловое хранилище, адаптер OCR, парсинг MRZ TD3, транслитерация по Приказу МВД № 889, дедупликация. **Ядро готово; экран проверки распознавания в работе.**
- S3 — шаблоны документов (8 из 14 написаны), шаблонизатор и генерация PDF/DOCX. **В работе.**
- S4–S6 — валидации V1–V11, статусы и автодействия, планировщик и пакеты, кабинет туриста и ПЭП, уведомления, финансы, аналитика. **Запланировано.**

Что проверено фактически: миграция схемы, шифрование/расшифрование с привязкой к полю, проверка пароля, защита от повторного использования кода 2FA, разбор MRZ с контрольными цифрами, транслитерация, неизменяемость аудит-лога. Не проверено: распознавание на реальных фото (в среде сборки нет tesseract), отправка SMS/email, эквайринг, обмен с 1С.

## Принятые допущения

- Одна организация, 3–10 сотрудников. PostgreSQL для боевой эксплуатации; SQLite для локального демонстрационного режима и быстрых тестов.
- FastAPI — транспортный адаптер. Бизнес-ядро не зависит от веб-фреймворка.
- Денежные суммы — целое число копеек, курс — десятичная строка; время хранится в UTC ISO 8601, показывается в Europe/Moscow.
- Каждая сущность имеет UUID и служебные поля. Audit-log содержит `deleted_at` для единства схемы, но запрещает любые UPDATE/DELETE; уничтожение его ПД регулируется отдельным регламентом.
- OCR не гарантирует точность на произвольном фото. Перед сохранением обязательны проверка человеком и явное подтверждение неуверенных полей.
- Согласия на обработку ПД оформляются отдельными документами от договора (ч. 1 ст. 9 ФЗ № 152-ФЗ в редакции с 01.09.2025).
- Моки — только development/test. Реальные интеграции и размещение в РФ требуют настройки владельцем.
- Тексты договоров и согласий — рабочие редактируемые проекты, не юридическое заключение. Реквизиты и правила въезда в демо вымышлены/учебные.
